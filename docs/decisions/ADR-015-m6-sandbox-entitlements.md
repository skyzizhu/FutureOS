# ADR-015：M6 本地沙盒商业化与独立研究权益

状态：用户授权 M6。保持原生 PostgreSQL/Redis，不进入 M7，不接入真实收款。

`SANDBOX_COMMERCE_ENABLED` 默认关闭。本地显式开启后展示 Mock 套餐/订单/确认页；
`LIVE_PAYMENTS_ENABLED=true` 被配置校验拒绝，不能仅改开关就开始真实扣款。
演示套餐金额不是正式定价，计划JSON由服务端读取，checkout冻结价格、币种、额度与期限；客户端只能选 plan_code。
现有 PaymentProvider 端口由 MockPaymentProvider 实现，M6 使用本地私有加密 key 经 HMAC 域分离导出的回调密钥，
不使用 M0 的公开测试密钥。确认模拟付款也走服务端签名/验证与同一事件处理，不靠前端成功标志开通。

支付事件按 provider/external_event_id 唯一、原始载荷 hash 检查冲突；校验订单参考、金额、币种和时间。
已验签事件、订单 paid、订阅、额度发放和流水在同一事务提交；不同事件ID重放同一已付款订单也不重复发放。
此处的验签只能证明本地 Mock 流程，不代表已经通过真实服务商 webhook 验收。

首次免费报告的 M4 额度/ledger 保持独立。套餐使用 grant、reservation、commerce ledger：
`units = available + reserved + consumed + revoked`，所有分量非负；每Job最多一个预留，源事件/用途流水唯一。
新主题完整报告预留1份，成功将 reserved 转 consumed，失败/取消/撤回授权/租约耗尽归还；旧主题免费更新不调用套餐预留。
订单退款只支持未使用整单：取消待完成研究、释放预留、撤销剩余额度，保留审计。已消费订单拒绝自动退款，不伪造资金返还。

同用户金融写操作使用 FOR NO KEY UPDATE；M6 Worker 最终提交先锁用户再锁Job，以统一取消/退款/消费的锁序。
私有报告、新版本引用、消费、站内通知、邮件请求、完成事件与Job结果在同一最终租约事务。
M4 的加密报告存储逻辑提取复用，不开放跳过审查或伪造已付费完成状态的客户端入口。

套餐订阅期限与研究节奏来自冻结配置；取消表示到期不续订，当前已购周期内保留服务。
沙盒不做自动续费/扣款；同一用户不叠加有效月度订阅。到期撤销未使用额度、停止周期调度。
周期研究还需要逐主题明确授权，每次完整服务使用1份订阅额度；邮件类型开关与此授权分离。
调度按用户/主题/周期slot幂等，不补发无界积压周期；余额不足记录错误后延后检查，不透支。
