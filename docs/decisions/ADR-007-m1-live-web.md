# ADR-007：M1 管理员手动 DeepSeek 联调

状态：已采用。2026-11-01，用户提供 Key 并授权配置与开始 M1。

Key 仅保存在忽略的本地 .env（0600）和 API 进程内的 SecretStr。启动器不把供应商 Key、数据库连接或管理员配置传给 Web 子进程。
DEMO_MODE 继续控制本地演示身份/Mock 研究，不再把它理解为“所有数据必为合成”；
LIVE_WEB_ENABLED 额外控制管理员的真实 Search/Fetch。普通研究演示仍只能使用 Mock。

真实请求只通过管理员手动入口：每次操作一个上游请求，无自动重试；每管理员每分钟5次、滚动24小时20次。
数据库以用户行锁序列化配额预留，失败也计入本地请求预算，避免隐式重试花费。
web_access_logs 保存操作、输入 hash、状态、HTTP 尝试数和时间，不保存 Key、搜索问题或供应商错误正文。
started 未完成代表状态未知，不宣称供应商没有计费。

Search 最多10条；Fetch 只返回2000字符预览与完整返回内容的 hash，不自动保留第三方全文。
用户先核对许可、时间与事实，再导入 metadata_only / excerpt（最多2000字符）/ authorized_full（上限100000字符）。
人工声明记录不等于自动完成许可审计。真实联调仅保留官方文档链接和元数据，无正文证据主张。
未知时间保留未知；网络新抓取不支持假历史 as_of。失败保留具名错误，不降级伪成功。

本轮实际各执行一次 Search/Fetch，均返回200并完成元数据入库；供应商接口次数由审计确认。
不调用 LLM、邮件或支付，不为未来研究自动开通周期采集。
实际计费金额以供应商账单为准，系统不根据响应状态自行宣称已扣/未扣金额。

未来生产认证、分布式账号级预算、跨用户共享研究和异步采集调度按后续阶段实施。
