# ADR-008：M2 冻结输入、互补融合、内部草稿 A

状态：已采用。用户于2026-11-01明确授权开始 M2；不实施 M3。

## 工作流与数据

沿用 apps/api → DB jobs → Worker → 独立 Core。研究提交返回202，管理员轮询状态。
M1 信号须重新通过事实、原文引用、数据标签、来源簇和 as-of 准入检查，不能直接信任统计的“独立来源数”。
来源/主张/案例/指标版本全部复制进 ResearchSnapshot，并以外键关联原对象；执行时不再查询“最新证据”。
库内反证检索最多100条同标签、当时已知的事实主张，按领域匹配；它不是穷尽的网络反证研究。

Core 按以下顺序执行：信号准入 → 互补融合 → 条件机制链/反向作用 → 历史类比 → 三类情景 → 统计基线 → 目标完整性裁决 → 草稿 A。
MVP 只提供两个具名机制模板：verifiable_agent、technology_diffusion。人工信号能力标签须由后续 Critic 核查。
只有必要能力齐备、至少两个支持信号且至少两个独立来源簇时才形成融合。三个转载不能充当三组证据。
未满足条件返回空融合和降级原因，不编造“新涌现”。支持全部生命周期枚举，默认 unknown；复查间隔为可检查的阶段规则，受目标期限约束。

历史类比按机制标签重合选择，明确案例当时前提、案例/当前领域与范围、关键差异、不可迁移处；
只使用截至研究 cutoff 已知的事件/结果。结果失败与成功都保留；未有失败结果时输出缺口说明。
这只是可解释的类比候选，不是通用因果推断、经过验证的相似度或未来成功概率。

数字主题使用同一指标定义/地区下最多最近24个可获取统计期；至少3期才计算 last-value 持平基线。
基线是对照而非主假设准确性的证据，不提供伪造区间或概率。未来统计期的投影不能冒充观测值。
未给目标、目标范围/验证规则未明确、指标口径不匹配、数据不足或没有独立互补融合时，只保留 hypothesis 或拒绝无效输入。

## 不可变与可重放

ResearchTopic 为稳定研究范围；WorldForecast 只在具备完整候选目标时建立稳定身份。
ResearchRun 冻结输入及 input/prompt/Core-code hash；ForecastDraft 仅保存不可变 A，包含所有阶段输出、原模型叙述和限制。
同一个目标可被多个运行引用，不因重试创建多个世界目标。同用户请求键唯一，同键不同内容409。
冻结草稿与任务 succeeded/完成事件在同一事务提交，并核对 Worker 租约 token。

运行的 Core Python 源码以内容地址保存在 .local/engine_versions/{hash}.zip。
重放采用被冻结的输入和模型响应；代码改变时验证原工件内容 hash，在隔离子进程中执行原 Core，
输入仅通过 JSON stdin，不使用 shell、不携带 Key/数据库/代理环境变量，不重新访问外部模型或数据源。
工件损坏/缺失明确409；依赖或 DTO 跨版本升级仍需保留对应运行环境，不能保证任意依赖版本兼容。
部署/备份要同时保留数据库、uv.lock 和这些代码工件；不要把无工件的旧开发记录声称为可恢复。
