# ADR-014：本地增量监控、免费更新与通信解耦

状态：M5 实施；继续原生 PostgreSQL/Redis，无 Docker，不进入 M6。

监控读取 M1 中已核实、在当前截止时间可获取、标签相同的本地资料。不主动联网搜索或调用付费模型。
来源导入仍使用 M1 管理入口；独立来源簇来自 M1，完全重复的文字不重复计数。
规则将重复信息归为 T0，单一新线索为 T1；独立反证或显式配置的连续指标绝对变化达到门槛为 T2。
T3 要求管理员明确断言、引用原假设及已核实反证，并冻结操作者/说明。语义核实仍依赖人工，不能将其称为自动事实判定。
默认每300秒检查、重大复查冷却21600秒、每主题滚动24小时最多12个任务、反证至少2簇。
没有通用的指标涨跌百分比；没有配置指标阈值时只观察。T3 可绕过普通冷却，不能绕过任务预算。

定向更新复用旧叙述及已知条件，Core 重算证据集合、融合、基线、类比和机制，不伪造新的模型推理。
M3 独立 Critic 在受限子进程审查；通过后才发布 vN+1，否则保留旧结论或标记待核实。
延续版本绑定当前父版本和完全相同的目标；允许目标窗口已开始，但不允许移动期限、范围、指标或验证规则。
旧版、研究输入、审查结果、监控运行与结果均追加写。归档 Core 可离线重放增量研究。

Job 租约最终提交事务锁定世界预测，原子提交新版本、监控结果和受影响用户的更新请求。
每个报告只替换原有世界主题的版本；画像编辑也只能免费重算原主题，不扩展新主题。
更新任务固定旧报告、画像快照、世界版本与原因；成功时提交加密新报告、站内通知、邮件请求和完成事件。
不建立或消耗首次额度预留；旧报告及其引用可继续查看。并发更新以固定基准防止旧任务覆盖新报告，调度器追赶落后的版本。

邮件偏好默认全部关闭；明确同意才能订阅，实际派发前再次核对。每用户/版本/用途唯一、首封最多一次、同类日/周冷却、每周最多5封。
摘要只有通用说明和鉴权的固定版本链接；收件人与退订令牌加密，不写入事件。退订令牌只保存 hash；退信 HMAC 验签、事件去重并抑制后续投递。
本地 transport 将持久化接受记录作为交付结果，支持幂等重放。真实 SMTP 实现 EmailProvider 端口，使用 TLS，但 DEMO Worker 不选择它。
当前配置只接受本地 DEMO 部署。真实邮件需要后续非 DEMO 发布闸门、真实域名/SMTP、投递不确定性处置和服务商沙盒验收；本轮不发送外部邮件。
M4 的邮件预览/本地模拟记录保留兼容，仅为旧演示，不等同于 M5 传输队列或真实投递。

原生 scheduler 与研究 worker 分离；关闭任何邮件偏好不影响监控、更新报告或站内通知。
当前扫描每轮最多100个世界预测、200份报告；这是单机原型批量上限，不承诺大规模覆盖或实时市场监控。
数据库 jobs/outbox/inbox 是任务事实来源，Redis 仅辅助唤醒；失败不产生报告完成通知或成功邮件。
