# 行业监听架构草案

## 行业列表与监听资格

首次完成引导画像时，将画像中的行业加入个人列表并排在首位。重复保存同一行业时复用列表项。跳过引导的用户可直接添加行业，也可将公开行业添加为自己的独立条目。每个条目都能保存自己的监听设置和报告历史。

| 规则 | 免费用户 | 付费用户 |
| --- | --- | --- |
| 监听数量 | 绑定一个行业 | 同时开启最多五个行业 |
| 关闭后 | 暂停运行，保留绑定，可重新开启原行业 | 释放一个监听位置，可用于其他行业 |
| 可选周期 | 月、季度、半年、年 | 日、周、月、季度、半年、年 |

拟定的绑定规则是，有画像时以画像行业作为首个免费监听行业。跳过画像时，在首次开启监听的事务中绑定选中的行业。暂停、移除列表项、后来补填或修改画像均保留已有绑定。行业名称可以编辑，监听范围绑定到稳定的行业标识，替换研究范围按新增行业处理。付费期间保留已有的免费绑定，付费用户同时运行的五个行业包含已开启的原免费行业。订阅到期后的恢复条件留待确认。

## 运行边界

1. **权益与计划。** 服务端按当前套餐校验行业归属、并发监听数和周期。行业条目、免费绑定、监听计划分别保存。同一账号的开启和暂停操作串行校验，避免同时开启时超额。历史 `waiting_rules` 开关继续作为待配置意愿，启用时明确确认周期和邮箱。
2. **调度与任务。** 调度器读取到期的监听计划，创建持久化任务。任务按计划和应运行时间去重，失败重试继续使用原任务。停用后停止安排后续任务，已有任务在提交报告及安排邮件前重新校验授权与计划版本。运行记录保存行业范围、资料截止时间和可用画像的最小授权快照。
3. **行业监听 Agent。** 每轮以当前监听行业为起点，检索可访问的公开资料，分析政策、市场、量化指标和社会变化，并追踪这些变化对其他领域的传导。以预测为核心，输出趋势、时间范围、依据、不确定性和重新判断的触发条件，再给出用户能执行的行动。无画像时提供基于行业的建议，有已授权画像时再按个人处境细化。监听周期决定任务多久运行一次，预测时间范围由研究问题决定。单轮编排见下文。
4. **报告与交付。** 成功完成后按行业归档一份私有监听报告，并在同一事务记录邮件待发送事件。邮件由独立任务向已验证且同意接收的邮箱投递。邮件失败时重试投递，复用原报告和交付记录。站内始终可查看已生成的历史报告。

## 与现有系统的接法

画像目前单独保存，首次保存时需补上个人行业列表的幂等接入。公开行业复制已有可复用的实现。现有 `IndustryTracking` 保存监听意愿，需补充免费绑定、监听周期、下次运行时间和运行记录。现有 M5 监控复查已有预测，M6 周期任务服务沙盒研究订阅。新增独立的行业监听任务类型，复用 PostgreSQL 任务、Worker 租约、加密报告版本和邮件队列。行业监听名额和现有单次研究额度分别结算，任务内部的搜索、模型及成本规则随 Agent 编排确定。

## 待确认的产品决策

- 首次开启时立即生成首份报告，还是等到第一个监听周期结束。暂停后恢复及修改周期时，如何计算下一次运行。
- 订阅到期时，原免费行业如何恢复。原行业使用日或周周期时，是否提示选择一个免费周期。付费前尚未绑定免费行业时，何时选择要保留的行业。

## 单轮 Agent 编排

| 阶段 | 工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 检索 | Search 分别查行业动态、市场与就业、政策、量化指标。模型审阅候选摘要，列出覆盖缺口和补搜词。 | 四个方向的初查均成功，已有候选资料，模型确认覆盖达标。 |
| 分析 | 补查反证及可比历史案例，Fetch 原文。模型可以沿研究行业或其他行业的真实演进过程补查事件、时间和结果。 | 原文能对上引句。量化引句包含指标、期间和值。直接资料达标或形成可引用的发展链，且已执行反证检索。模型确认达到写作条件。 |
| 写报告 | 使用通过校验的资料生成条件预测、机制、替代情景、观察信号与证伪条件。每项行动对应预测，提供触发条件、耗时、复查时间、结果检查和停止条件。 | 直接证据预测引用至少两个站点与量化引句。依靠历史案例的预测标为类比情景，关联完整发展链并说明迁移条件与验证信号。已接受的反证须在报告中有对应引用，行动须指向存在的预测。 |

模型已有知识可以给出检索方向。证据行业的发展链包含背景、按时间排列的实际节点、最后可观察到的结果、传导机制、可比条件和关键差异。每个节点关联原文引句及链接。节点名称和数量随案例变化，同一篇完整研究可以为多个节点提供不同引句。缺少关键环节时继续补查。站点多样性与文本去重只是初筛，来源转载关系、数据口径、事实真伪和因果强度仍待独立审查，当前输出为草稿。

默认预测期限为 180 天，可在入口按研究问题指定。覆盖最多评估两次，证据最多评估三次。单轮上限为 14 次搜索、16 次抓取、7 次模型请求及 120 秒。补搜缺乏新资料、证据不足或报告校验失败时，保留缺口和研究记录。Search 摘要用于筛选。Fetch 保留来源链接、内容哈希及至多 1400 字符的摘录。

画像检索范围使用标准行业标签与经授权的国家范围。自填细分默认采用上一级行业，操作者可以显式指定公开的研究范围。岗位文本、任务、目标和可用时间在本地筛选行动。年龄、性别等个人信息留在画像侧。报告包含通用行动草案，勾选个性化与小步试验授权且配置时间预算后，可额外返回预算内的行动清单。

## 本地执行与验收

运行 `uv run python -m scripts.industry_agent` 可重现一次 DEMO，输出结构化的来源、证据、预测与行动。`--horizon-days` 指定期限。`--profile` 可读入本地 `ProfileInputV1` JSON。显式 `--industry` 适用于没有画像的研究，或已明确可公开检索的自填范围。

真实提供商入口要求显式选择 live 并具备已有的 Search、Fetch 和模型配置。Fetch 沿用域名白名单。本轮使用合成来源和确定性模型测试，产品定时触发、私有报告归档与邮件交付仍属于监听计划接入阶段。
