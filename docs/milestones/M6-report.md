# M6 实施与验收报告

日期：2026-11-02。**M6 本地沙盒范围已完成，最终原生全栈自动化验收通过；未进入 M7。**
继续使用原生 PostgreSQL、Redis、API、research worker、scheduler 和 Web，无需 Docker。
本轮没有真实扣款、真实邮件发送或新增付费模型/检索调用。

## 事务、边界与隐私

- Migration `0010_m6` 新增11张业务/计量表，全库72张业务表。支付事件、流水、quote、研究请求与成本观测追加写；订单、订阅、grant、reservation 仅允许受限状态变化。
- 回调使用 M6 专用派生密钥验签，不接受 M0 的公开测试密钥。provider/event_id 唯一、载荷 hash 冲突检查、订单参考/金额/币种校验、订单与grant唯一共同防重。
- 数据库回退在已有支付事件或套餐研究请求时被阻断，避免降级删除审计；空库往返迁移和元数据对比通过。
- 额度守恒：`units = available + reserved + consumed + revoked`；非负约束、owner复合外键、Job预留唯一、流水来源/用途唯一及用户行锁防止重复消费。
- M6 最终提交按用户→Job锁序处理；报告、版本引用、消费、站内通知、邮件请求、Job结果和Outbox同事务。
- 复用 M4 加密报告存储，保留原首次免费 ledger 及一次消费限制。M5 原主题更新不进入新套餐预留/消费逻辑。
- 世界研究只接收规范范围和本地合成证据，个人画像不进入共享研究或供应商。报告使用明确授权的最小快照，撤回选填授权取消未完成任务并归还预留。
- 报告时间不早于所引用世界版本的发布时间，避免把提交时刻错误显示为新预测发布前的报告生成时刻。
- 研究输入、叙述、Core工件、草稿与固定来源/主张/指标引用可离线重放；已在执行的共享复查不被套餐任务抢占。
- Core 仅新增契约类型，不引入商业逻辑、HTTP或数据库依赖。Pydantic 导出106个域 Schema/OpenAPI/TypeScript。

取舍：[ADR-015](../decisions/ADR-015-m6-sandbox-entitlements.md)、[ADR-016](../decisions/ADR-016-m6-guided-study-costs.md)。运行和恢复：[M6-runbook.md](M6-runbook.md)。
