# 注册、登录审计与反滥用

用户提交通过格式校验的注册或登录请求后，记录服务端时间、请求 ID、已识别账号、操作、结果和拒绝代码。成功记录与会话在同一数据库事务提交。拒绝记录独立保存，保留已提交的限流与验证码失败计数。管理员安全页显示最近 100 条，沿用所有者权限与 MFA 检查。

浏览器在同源认证入口获得随机 HttpOnly Cookie，默认 30 天。服务端仅保存域分离 HMAC 指纹。直接 API 请求缺少浏览器标识时，审计使用请求头指纹作为线索。指纹不参与身份授权。IP、浏览器与系统标签、限定长度的 UA 和语言加密保存。IP 取 API 实际连接地址，忽略客户端提供的转发头。经本地 Web 代理时通常为回环地址，公网客户端 IP 需要可信代理配置。凭据及会话令牌不从认证正文进入审计。

访问记录默认保留 30 天，由原生调度器删除过期数据。账号导出包含本人成功访问，账号删除及恢复重放清理其关联记录。历史备份按已有备份策略处理。

在既有账号、来源、全局准入之外，增加滚动窗口每浏览器默认 20 次。登录、注册提交和验证码相关操作共用该维度。验证码全局滚动 24 小时默认接受 120 条请求，在同一事务锁下检查和预留，含被抑制的找回请求。继续执行邮箱冷却、猜码上限和证明单次消费。认证 Web 代理按实际字节流限制请求体为 5000 字节。

认证查询使用 SQLAlchemy 绑定参数。复核现有原始 SQL 调用点，认证请求参数未拼接进 SQL。回归覆盖恶意邮箱、包含注入语句的密码、伪造 IP 头、重放、跨邮箱浏览器限流和并发邮件总量限制。

迁移为 `0020_auth_access`。`make contracts` 生成 155 个领域 Schema 与 API 类型。`uv run pytest tests/security/test_auth_access.py tests/security/test_login_protection.py -q` 为 10 passed（7.80 秒）。

`make check` 通过 Ruff、ESLint、TypeScript 与 100 个源文件的 mypy 检查，pytest 为 450 passed（188.62 秒）。`make build` 通过。`make local-verify` 在隔离 PostgreSQL 中通过 450 项测试（182.79 秒）、队列冒烟与 22 条浏览器流程（2.8 分钟）。浏览器验收包括 HttpOnly 指纹 Cookie、注册与登录关联、管理员审计页与超长 UTF-8 请求。输出见 `.local/auth-access-{contracts,check,build,native}.log`。
