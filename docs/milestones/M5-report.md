# M5 实施与验收报告

日期：2026-11-02。范围为 M5；未实施 M6、支付、新主题权益或付费周期服务。
**M5 已实现，最终原生全栈自动化验收通过；未进入 M6。**
本地部署继续使用原生 PostgreSQL、Redis、API、research worker、scheduler 和 Web，无需 Docker。

指标门槛必须按具体指标配置绝对变化与连续期数，没有通用涨跌百分比。M5 不声称提高预测准确率。

## 基础架构与接口

- Migration `0009_m5` 新增12张监控、报告更新请求、通知、偏好/审计、本地邮件/尝试、退订与退信表；全库61张业务表。
- 8张 M5 审计/请求/通知表追加写；延续预测数据库触发器校验父版本、同一世界目标与完全相同的目标内容。
- 报告更新、通知、已读与邮件使用复合外键校验 owner；私有正文与邮件载荷加密，不将画像或收件人写入公共事件。
- `ReviewRepository` 支持由租约持有者统一提交；技术故障可将已在事务内生成的新世界版本与报告更新请求一起回滚。
- Pydantic 导出97个域 Schema、OpenAPI 与 TypeScript；Core 仍只依赖 Pydantic/标准库，SMTP 与数据库留在 infra。
- SMTP 实现现有 EmailProvider 端口并有 TLS/固定 Message-ID 测试；当前 DEMO Worker 只选择本地 transport，未调用真实 SMTP。

设计取舍见 [ADR-014](../decisions/ADR-014-m5-monitor-updates.md)，故障处理见 [M5-runbook.md](M5-runbook.md)。本机数据库核对见 [M5-database.json](evidence/M5-database.json)。

## 入口与范围限制

- 管理员：[拐点监控](http://127.0.0.1:3100/admin/monitor)，使用原本地管理员登录。选取 DEMO 主题后可加入合成变化并查看复查结果。
- 用户：[我的报告](http://127.0.0.1:3100/dashboard)、[通知与订阅](http://127.0.0.1:3100/notifications)。免费更新只覆盖原主题，不扣新的研究权益。
- 当前是本地已核实输入的规则/结构化增量复核，非自动持续抓取整个互联网。T3 语义核实依赖管理员声明与证据引用，尚未证明可自动判定事实真伪。
- 目前每轮最多扫描100个世界预测、200份报告；多机分片、广泛行业覆盖与服务级时延保障未实现。
- 周期任务和通知调度已实现；付费周期研究、新主题计费与支付留在 M6。
- `delivered_local` 仅表示本地接受。真实 SMTP、真实邮件送达率、投递不确定性的服务商核对与生产发布仍未启用/验收。
- M4 原有一次模拟邮件预览接口保留兼容，不视为真实投递或 M5 服务商发送记录。
- 开发期 PostgreSQL 全量测试曾发生一次报告初始化 `JOB_FAILED`，未稳定复现；已增加只记录错误类和代码位置的诊断，定向7项及后续全量复测通过。不能声称已确定该次失败的根因；生产前仍需持续稳定性观察。
- 保留1项 Starlette TestClient 弃用提示；独立人工质量评审和真实前瞻到期评估仍待完成，不能根据 DEMO 测试给出真实准确率。

本轮不需要新数据库账户或 DeepSeek Key。已沿用本地私有配置，未新增付费模型/检索调用、真实邮件发送或支付。
