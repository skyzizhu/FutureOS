# 服务端 Chat Harness

## 生效边界

- 浏览器提交问题和模型授权，服务端按账号校验会话和行业。模型只能产生结构化回复或添加行业的提议。服务端独立检查添加意图，只有本人确认对应提议后才写入。模型返回后再次校验会话有效性和行业访问权限。
- 聊天模型使用固定系统规则与单独序列化的对话数据，不注册网络、数据库、发布、支付或邮件工具。聊天正文不进入运行日志。
- 单轮行业研究保留固定的 Search、Fetch 和模型端口及调用上限。补搜词经过服务端过滤，抓取只从搜索结果选取，真实抓取的域名及网络检查由现有适配器负责。报告草稿必须通过结构、证据与引用校验。

## 上下文、记忆与审计

- 对话原文、压缩出的研究要点和运行元数据随本人会话加密保存。删除会话会一并删除这部分数据，本人的数据导出可查到记录。
- 仅从用户消息提取有限词表内的地区、期限和决策主题，保存原消息位置。新提及覆盖同类旧提及。提及可能有否定或修正，模型需结合近期内容核实。记忆范围为当前会话。
- 每次模型请求最多七条近期消息，系统提示与数据合计不超过 10000 个 UTF-8 字节。超预算从最早的完整轮次开始缩减，当前问题保留。模型输出最多 1024 token。
- 前端授权明确涵盖当前行业、近期对话和本会话研究要点。接口中的记忆传输需要显式授权，旧调用方默认只发近期消息。疑似凭据输入被拒绝，历史消息对外发送前遮蔽匹配到的凭据和邮箱。
- 回复校验覆盖数据结构、凭据和主动内容。调用记录只存策略版本、时间、关联 ID、上下文摘要哈希、大小、耗时、供应商可用 token 用量及动作判定。模型输出拦截记录使用关联 ID 和安全错误码。
- 保留单账号 15 分钟 10 次和一个并发调用，增加整个实例集群默认每分钟 60 次、同时最多 8 次的 PostgreSQL 事务配额。请求开始前扣入调用预算，超时及失败占用同一次调用。迁移 `0022_chat_harness` 新增实例级配额和在途索引。

## 发布边界

这一轮在聊天 API 和独立行业研究编排中接入上述约束。聊天深度研究的持久任务、工具轨迹、取消与恢复需要在 Worker 接入时验收。上线前需要以多实例压测验证预算与故障恢复，并用真实供应商的隔离样本复核注入、数据外传和输出语义。规则能降低已覆盖的风险，安全边界以服务端工具权限、数据隔离和确认事务为准。

## 验收

- 专项测试 14 项通过，覆盖旧条件被覆盖、完整轮次压缩、凭据保护、恶意工具建议、账号间配额和模型调用期间会话撤销。
- `make contracts` 生成 157 个领域 Schema 和 API 类型。
- `make check` 通过，Ruff、ESLint、TypeScript、mypy 104 个源文件和 461 个 pytest 测试。
- `make build` 通过，Next.js 预渲染 16 个静态页面。
- `make local-verify` 通过，原生 PostgreSQL、Redis 与任务冒烟通过，461 个 pytest 测试和 22 条 Playwright 流程。
- `make up` 已恢复服务，API 就绪接口返回 HTTP 200。模型路径使用模拟响应验收。
